# 狼人殺 Online

3D 線上狼人殺。建立房間、把連結傳給朋友，就能遠端一起玩——系統自動擔任法官，不需要有人當上帝。

- **31 種角色**，可自由組合牌組，內建 15 種經典板子
- **遠端連線**：4–18 人，手機與電腦都能玩，斷線重整後會回到原本的座位
- **3D 村莊**：玩家圍著營火而坐，日夜交替、發言聚光、票型連線
- **一眼認人**：座位號碼 + 專屬顏色 + 頭像 + 暱稱，3D 名牌與側邊名單完全對應；還能替每個人加上只有自己看得到的標記
- **自動法官**：語音旁白、計時、夜晚結算、警長競選、PK、遺言、技能觸發全自動
- **電腦玩家**：人數不夠時可以加入電腦補位

## 本機開發

需要 Node.js 20.9 以上。

```bash
npm install
npm run dev        # http://localhost:3000
```

沒有設定資料庫時，房間會存在記憶體裡（重啟伺服器就消失），適合直接試玩。

```bash
npm test           # 規則測試 + 隨機對局壓力測試
npm run typecheck
npm run build
```

## 部署到 Vercel + Neon

1. **把專案推上 GitHub**
   ```bash
   git init
   git add .
   git commit -m "狼人殺 Online"
   git branch -M main
   git remote add origin https://github.com/<你的帳號>/<repo>.git
   git push -u origin main
   ```
2. **在 Vercel 匯入專案**：New Project → 選擇剛剛的 repo。框架會自動偵測為 Next.js，不需要改任何設定。
3. **連接 Neon**：專案的 Storage 分頁 → Create Database → 選 Neon → 連接到這個專案。Vercel 會自動注入 `DATABASE_URL` 環境變數。
4. **重新部署**一次讓環境變數生效。資料表 `ww_rooms` 會在第一次有人建立房間時自動建立，不需要手動跑 migration。

> 建議把 Vercel Functions 的區域（Settings → Functions → Region）設成和 Neon 資料庫相同或相鄰的區域，操作反應會更即時。

### 在本機連接 Neon（選用）

把 `.env.example` 複製成 `.env.local`，填入 Neon 的連線字串（用 pooled 的那一條），然後：

```bash
npm run db:check   # 驗證連線、建表、讀寫與樂觀鎖
npm run dev
```

## 怎麼玩

1. 在首頁設定暱稱、頭像、代表色，按「建立房間」。
2. 按「複製邀請連結」傳給朋友；朋友打開連結、設定外觀後就會出現在營火旁。
3. 房主在右側選擇板子或自訂角色、調整規則，按「開始遊戲」。
4. 輪到你行動時，下方會出現行動面板：**點選 3D 場景中的玩家或左側名單**來選擇目標，再按按鈕確認。
5. 發言階段建議搭配 Discord / LINE 語音通話；遊戲內也有文字聊天（公開、狼隊、亡者三個頻道）。

房主在遊戲中可以按「跳過」立即結束目前階段（例如有人掛機），或「中止」回到大廳。

### 可調整的規則

警長競選、屠邊／屠城、女巫自救（僅首夜／全程／不可）、夜晚遺言（僅首夜／每晚／無）、同守同救是否死亡、出局者上帝視角、文字發言限制，以及發言、行動、投票的時間。

### 採用的規則判定

狼人殺各地規則不盡相同，這裡採用較通行的版本：

- 夜晚順序：盜賊 → 丘比特 → 混血兒 → 野孩子 → 夢魘 → 魔術師 → 攝夢人 → 守衛 → 狼人 → 狼美人 → 石像鬼 → 女巫 → 預言家 → 通靈師 → 狐狸 → 獵魔人 → 禁言長老 → 烏鴉 → 吹笛者
- 女巫同一晚只能用一瓶藥；解藥用掉後不再得知死訊
- 被毒死、殉情、被魅惑殉情的獵人與狼王不能開槍；狼王自爆也不能開槍
- 警長競選在第一天公布死訊之前舉行；競選中狼人自爆則延到隔天，隔天再自爆則警徽流失
- 放逐平票進入 PK，PK 台上的玩家不能投票，再平票則無人出局
- 勝負在有人出局的當下立即判定；若同一晚雙方同時達成條件，以狼人勝利為準
- 角色已出局時，法官仍會照常「喚醒」他並等待一段隨機時間，避免從夜晚的節奏猜出誰死了

## 架構

```
src/game/        純 TypeScript 的規則引擎（不依賴任何框架）
  engine.ts        階段機、夜晚結算、投票、技能、勝負判定
  view.ts          產生「單一玩家看得到的畫面」，其他人的身分不會送到瀏覽器
  bots.ts          電腦玩家
  runtime.ts       計時器推進與操作分派
src/lib/         儲存層（Neon / 記憶體）與房間服務
src/app/api/     建立房間、加入、操作、長輪詢
src/components/  3D 場景（React Three Fiber）與遊戲介面
tests/           規則測試與隨機對局壓力測試
```

幾個設計重點：

- **伺服器權威**：所有操作都送到伺服器，由規則引擎驗證後才生效；每位玩家只會收到自己該知道的資訊。
- **即時同步不需要常駐伺服器**：Vercel 的函式無法維持 WebSocket，所以採用長輪詢——版本號沒變時連線掛住，一有變化立刻回傳。同一個執行個體內的更新是即時推送，跨執行個體則每 0.8 秒查一次版本號。
- **計時器惰性推進**：期限存在資料庫，由下一個進來的輪詢負責推進，所以沒有人在線時遊戲會自然暫停。
- **樂觀鎖**：整個房間狀態存成一筆 JSONB，以版本號防止同時操作互相覆蓋。
- 超過兩天沒有活動的房間會被自動清除。
